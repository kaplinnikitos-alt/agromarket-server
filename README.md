# АгроМаркет API

Backend для учебного проекта «АгроМаркет» на Node.js + Express + PostgreSQL. Отдаёт товары каталогу, умеет создавать, изменять и удалять их (CRUD) и принимает оптовые заявки из React-формы. Frontend: репозиторий `agromarket-react`.

## Запуск

1. Установить PostgreSQL, создать базу `agromarket`
2. Скопировать `.env.example` в `.env` и указать свой пароль
3. `npm install`
4. `npm run db:init`        # создать таблицы и загрузить товары
5. `npm run dev`            # http://localhost:3000

Запускать из папки `agromarket-server` (пути к `db/schema.sql` и `data/db.json` считаются от неё). Нужен Node.js 18.11+ (режим `--watch`).

## Структура

```
agromarket-server/
├── data/
│   └── db.json              # источник начальных данных для seed
├── db/
│   ├── schema.sql           # описание таблиц products и orders
│   ├── pool.js              # подключение к PostgreSQL (пул соединений)
│   └── seed.js              # создать таблицы + залить товары
├── middleware/
│   ├── logger.js            # логгер запросов
│   └── errorHandler.js      # централизованная обработка ошибок
├── routes/
│   ├── products.js          # /api/products (CRUD)
│   └── orders.js            # /api/orders
├── postman/
│   └── agromarket.postman_collection.json
├── .env                     # не попадает в Git
├── .env.example
└── server.js
```

Порядок middleware в `server.js`: `cors` → `express.json()` → `logger` → маршруты → обработчик 404 → `errorHandler`.

## Лабораторная 6 — ответы

- **Ошибки из части 2:**
  - `price = -5` — сработало ограничение `CHECK (price >= 0)` (код 23514, ограничение `products_price_check`).
  - товар без `name` — сработало `NOT NULL` (код 23502).
  - заявка с `product_id = 9999` — сработал внешний ключ `REFERENCES products(id)` (код 23503): такого товара нет.
- **SQL-инъекция:** при подстановке значения прямо в строку запрос `zzz' OR 1=1 --` вернул все товары (условие `OR 1=1` всегда истинно, остаток запроса закомментирован), а одна кавычка `'` сломала запрос — ответ 500. С параметром `$1` оба адреса возвращают пустой список со статусом 200: значение приходит как данные и не становится частью SQL.
- **Двойная защита quantity:** без JS-проверки заявка с `quantity = 5` не сохраняется — база отклоняет её по `CHECK (quantity >= 10)`, и `errorHandler` отвечает 400 «Значение не проходит проверку в БД». JS-проверка всё равно нужна: она быстрее (не ходим в базу) и даёт понятное сообщение «Минимальный объём заказа — 10 кг», а CHECK — последний рубеж, если проверку обойдут или забудут в другом месте кода.
- **Что стало с заявкой после удаления товара:** заявка осталась, у неё `product_id` стал `NULL` (`ON DELETE SET NULL`), а `product_name` в `/api/orders` — `null` (поэтому в запросе `LEFT JOIN`).

## Вопросы для защиты (кратко)

- **Первичный и внешний ключ:** первичный (`id SERIAL PRIMARY KEY`) однозначно определяет строку. Внешний (`orders.product_id REFERENCES products(id)`) связывает заявку с товаром. `ON DELETE SET NULL` — при удалении товара у его заявок `product_id` становится `NULL`, сами заявки не пропадают.
- **Ограничения orders:** `NOT NULL` для `name`, `email`, `quantity`, `status`; `CHECK (quantity >= 10)`; `CHECK (status IN (...))`; внешний ключ `product_id`. При нарушении база отклоняет запись с ошибкой, API переводит её в 400.
- **CRUD:** Create — INSERT — POST — 201; Read — SELECT — GET — 200; Update — UPDATE — PUT/PATCH — 200; Delete — DELETE — DELETE — 204.
- **PUT и PATCH:** PUT заменяет ресурс целиком (не переданные поля станут `NULL`), PATCH меняет только переданные. DELETE возвращает 204, потому что возвращать нечего: ответ успешный, но без тела.
- **LEFT JOIN:** показывает все заявки, даже если товара нет (`product_name` будет `null`); обычный JOIN такие заявки потерял бы.
- **Обработчик ошибок:** Express отличает его по четырём параметрам `(err, req, res, next)`. Клиенту не отправляют текст ошибки 500, чтобы не раскрывать устройство сервера (имена таблиц, пути к файлам).
- **Пул и dotenv:** пул держит готовые соединения, открывать новое на каждый запрос дорого. `import 'dotenv/config'` должен быть первым, иначе `db/pool.js` прочитает `DATABASE_URL`, когда он ещё `undefined`.
